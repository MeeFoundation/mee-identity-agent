## Context

`apps/app-ux-flows` is a Vite + React 19 SPA using TanStack Router, Jotai and i18next. It has no CSS today:
- `index.html`, `routes/root.tsx` and every component render unstyled HTML.
- Only `ProminentQuickAction` has an inline style.

Flow screens never import UI directly. They get `Button`, `Checkbox`, `Header` and `TextField` through `useFlowComponents()`, from `defaultComponents` in `src/shared/ui/default-components.ts`. Variants can replace any of them. So restyling `src/shared/ui/*` restyles every flow without touching screens.

Routing (`src/routes/`):
- `root.tsx` renders `<main><Outlet/></main>`.
- `home.tsx` serves `/`.
- `flow.tsx` redirects `/flows/$flowId` to the flow's initial screen.
- `flow.$screenId.tsx` renders `FlowRunner` and passes it `exit()`, which navigates to `/`.
- `FlowRunner` switches between the active screen and `CompletionView` internally.

Constraints:
- Biome 2.2.4 is the only linter and formatter, and `noUnknownAtRules` is already off.
- Knip runs per app.
- Path aliases are `@/app`, `@/routes`, `@/shared` and `@/slices`, defined in both `vite.config.ts` and `tsconfig.json`.
- `@mee/ui` is React Native only, so it can't be reused here.

## Goals / Non-Goals

**Goals:**
- One token source (CSS custom properties) that both Tailwind utilities and shadcn components read.
- shadcn components on Base UI primitives, copied into `src/shared/ui` and owned by the app.
- The device frame is presentation only. It doesn't change routing, flow state or the variant logic.

**Non-Goals:**
- Dark mode. Tokens are structured so a `.dark` override could be added later, but none is defined now.
- A generic, reusable device-frame library, or other device models (Android, iPad).
- Pixel-perfect coverage of every Figma variant that no flow uses, such as text fields with icons, prefixes or flags.

## Decisions

### 1. Tailwind CSS v4 + shadcn (Base UI) for styling
- **Choice:** Tailwind v4 through `@tailwindcss/vite`, with shadcn components generated by the shadcn CLI in its Base UI flavour (`@base-ui/react`).
- **Why:** this was requested, and the Figma system is already Tailwind-shaped. Its gray scale equals Tailwind `slate`, its error scale equals Tailwind `red`, and spacing is Tailwind's 4px scale, so almost nothing needs translating.
- **Alternatives:**
  - CSS Modules + tokens: no new dependencies, but no shadcn.
  - Radix-based shadcn: rejected, because Base UI was explicitly requested.

### 2. Token layer: one stylesheet, three tiers
`src/app/styles.css` is imported once from `src/main.tsx`. It holds three tiers:

1. **Primitives** in `@theme`, named after Figma.
   - `--color-brand-50…950`, `--color-gray-*`, `--color-error-*`, `--color-warning-*`, `--color-success-*`, `--color-orange-*`, `--color-purple-*`.
   - Tailwind's default colour palette is cleared (`--color-*: initial`), so only design-system colours can be used.
   - Text sizes `--text-xs…7xl` with their `--line-height` pairs from Figma. Tailwind's defaults differ, for example `xl` is 28 in Tailwind and 30 in Figma.
   - `--font-sans: "Public Sans Variable", …`, `--tracking-normal: 0.005em` (Figma letter-spacing 0.5%).
   - Spacing stays at Tailwind's default `--spacing: 0.25rem`, which matches Figma exactly.
2. **Semantic roles** for shadcn, defined in `:root`:

   | Role | Value |
   |---|---|
   | `--background` | white |
   | `--foreground` | `#1e293b` (Figma `text/default/body`, gray-800) |
   | `--primary` | brand-500 |
   | `--primary-foreground` | white |
   | `--secondary` | brand-50 (Figma `surface/brand/soft`, Secondary button fill) |
   | `--destructive` | error-700 (Figma `surface/error/solid`, Danger button fill) |
   | `--muted` | gray-100 |
   | `--muted-foreground` | gray-500 |
   | `--border` / `--input` | gray-300 |
   | `--ring` | `#4f868e66` (Figma `alpha/outline/brand`, brand-500 at 40%) |
   | `--radius` | 8px (`rounded/lg`) |
3. **Exposure:** an `@theme inline` block exposes the roles as Tailwind colours (`bg-primary`, `text-muted-foreground`, …).

Exact values are taken from the Figma variables during implementation using `get_variable_defs` on the component nodes. `brand-700` was missing from the colours-frame export, so it gets fetched from a node that uses it.

**Alternative:** generate tokens from Figma automatically (Tokens Studio / a script). Rejected for now: it needs Figma API credentials in the build and adds a pipeline for a token set that rarely changes.

### 3. Font: self-hosted Public Sans
- **Choice:** `@fontsource-variable/public-sans`, imported in `src/main.tsx`. The font ends up in the static build, so it works offline and needs no third-party request during participant sessions. This is required by the "Font is available offline" scenario.
- **Alternative:** Google Fonts `<link>`. Rejected because it depends on the network and sends participants' IPs to Google.

### 4. Components: shadcn source in `src/shared/ui`, with thin contract wrappers
`components.json` points the shadcn CLI at this app's structure:
- `ui` → `@/shared/ui/primitives`
- `utils` → `@/shared/lib/cn`

The generated primitives (`button`, `input`, `label`, `checkbox`) live in `src/shared/ui/primitives/`. The existing contract components wrap them:

| File | Contract kept | Built from |
|---|---|---|
| `button.tsx` | `{children, onClick, disabled}` + optional `size`, `variant`, `tone` | primitive `button` with a CVA matrix |
| `text-field.tsx` | `{label, value, onChange(value)}` | `label` + `input` |
| `checkbox.tsx` | `{label, checked, onChange(checked)}` | Base UI `checkbox` + `label` |
| `header.tsx` | `{title, onBack?}` | custom, App Topbar "Regular Page" without the status bar |

The Button CVA uses three axes, `size` (s/m/l/xxl), `variant` (filled/outlined/link) and `tone` (primary/secondary/tertiary/danger), because Figma separates style from type. shadcn's single `variant` axis can't express 12 combinations cleanly. The defaults are `m`, `filled` and `primary`, so existing call sites render as the spec requires.

Figma facts that shape the matrix: buttons use `rounded/xl` (12px) for S/M/L and `rounded/2xl` (16px) for XXL. Filled primary is a gradient from brand-700 to brand-500 (`Gradient/Button/Brand`); hover is flat brand-800, focus is flat brand-700, and disabled is 60% opacity. Focus rings are 3px at 40% alpha of the tone (brand-500, gray-500 or error-500).

**Why wrappers instead of changing callers:** flows depend on `DefaultComponents`, so keeping those props means no screen changes. This is required by "Existing component contracts preserved". It also lets the primitives follow shadcn upstream.

Flow-specific components (`PetCard`, `QuickAction`, `ProminentQuickAction`) and `CompletionView` are restyled in place with Tailwind classes, plus the design-system `Button` where a button exists. `ProminentQuickAction`'s inline style is replaced by `<Button size="xxl">`-equivalent styling.

Icons come from `lucide-react` (shadcn's default): back chevron, checkbox check. The status-bar glyphs come from Figma (Decision 6).

### 5. Device frame: route-level wrapper, not a layout route
- **Choice:** a new slice `src/slices/device-frame/` exporting a `DeviceFrame` component, used only in `routes/flow.$screenId.tsx` around `FlowRunner`. The chrome (back link and title) is rendered by the route, which already has `flow.titleKey`, `flow.variantId` and `exit`.
- **Why:** with option C the frame exists only on flow routes. A pathless layout route would change the route tree, and the `flow.tsx` redirect would need re-parenting, for no gain. `CompletionView` renders inside `FlowRunner`, so it is framed automatically.

Structure (desktop):

```
page (h-dvh, centred, bg gray-100)
+-- chrome: [< Back to all flows]  Flow title  (dev: variant id)
    (top-left corner, out of flow, at lg and up, so a 900px-tall window fits the 876px device at full size; above the frame below lg)
+-- scaler (computed scale)
    +-- bezel (rounded ~55px, dark gray, padding ~12px)
        +-- screen (393x852, rounded ~44px, overflow hidden, flex col, bg white)
            +-- StatusBar      (aria-hidden, shrink-0, 64px per Figma)
            +-- scroll area    (flex-1, overflow-y-auto, overscroll-contain)   <- flow screen
            +-- HomeIndicator  (aria-hidden, shrink-0, 21px per Figma)
```

- **Scroll reset:** a layout effect on `screenKey` sets the scroll area's `scrollTop` to 0. Keying the scroll area by `screenId` was the first idea, but `FlowRunner` is its child, so a key change would remount it and reset the flow's Jotai store on every navigation.
- **Screen layout:** flow screens render a bare `<section>` that starts with the shared Header. The scroll area applies a `flow-screen` utility (in `styles.css`) that lays the section out as a column with 16px gaps and 16px side gutters below the header, so screen code doesn't change.
- **Scaling:** a small hook observes the size of the area left for the frame (a ResizeObserver, so the chrome and margins are already subtracted) and computes `scale = min(1, availableH / frameH, availableW / frameW)`. It's applied as `transform: scale()` on the bezel, and the wrapper's box is sized to the scaled dimensions so layout doesn't leave dead space. The alternative, CSS `zoom`, is now cross-browser but changes the coordinate space for pointer events in older Safari. Transform is predictable.
- **Phone fallback:** handled purely with CSS (`max-[480px]:` variants). At that size, chrome, bezel, status bar and home indicator are `hidden`, the screen is `w-full h-dvh rounded-none`, and the scale is forced to 1. No JS branch is needed, so nothing flickers on first paint.

### 6. Status bar and home indicator from Figma
- **Choice:** built as small React components using inline SVG for the signal, Wi-Fi and battery glyphs and the Dynamic Island pill. The SVGs are exported from node `5726:3310` (the Dynamic Island variant) through the Figma MCP asset download, then cleaned up (fills set to `currentColor`).
- **Why:** inline SVG scales crisply with the frame transform and needs no extra network requests.
- **Alternative:** a PNG of the whole status bar. Rejected because it blurs when scaled.

### 7. Home page
`home-page.tsx` keeps its props and behaviour. Only its markup changes:
- a top header with the app title and the "Start new test session" Button (`variant=outlined`)
- a responsive grid of flow cards
- in each card, Buttons for start or each explicit variant, and the dev-only assigned-variant label as small muted text

`routes/root.tsx` drops the bare `<main>`, and each route owns its own page layout. Otherwise the framed page would inherit home-page padding.

## Risks / Trade-offs

- **Biome 2.2.4 may not parse Tailwind v4 at-rules** (`@theme`, `@theme inline`, `@custom-variant`, `@utility`). Proper support (`css.parser.tailwindDirectives`) arrived in Biome 2.3.
  - Mitigation: keep the Tailwind-specific CSS in one file, and check `pnpm lint` right after adding it.
  - If it fails, ask the user to choose: bump Biome at the root (that affects all workspaces and needs approval), or exclude that one file from Biome.
  - Outcome: it failed; Biome was bumped to 2.3.15 at the root with `css.parser.tailwindDirectives` enabled.
- **Knip may report `tailwindcss` or the font package as unused,** because they are referenced only from CSS or a side-effect import.
  - Mitigation: the side-effect import in `main.tsx` counts as a use. For `tailwindcss`, which is used only through `@import` in CSS, check knip's output and add a narrowly scoped `ignoreDependencies` entry if needed.
  - Outcome: knip flagged `tailwindcss`. Adding `css` to knip's `project` glob lets it follow the `@import`, so no `ignoreDependencies` entry was needed.
- **shadcn CLI assumptions:** the CLI expects `@/*` aliases and a root `src/index.css`.
  - Mitigation: an explicit `components.json` with this app's aliases.
  - Verify after init that it didn't rewrite `tsconfig.json` or `vite.config.ts` beyond the Tailwind plugin, and revert anything extra.
- **Base UI package naming:** it's now `@base-ui/react`, formerly `@base-ui-components/react`. Use whatever the shadcn CLI installs, and keep one of them only.
  - Outcome: `shadcn init` (4.21.4) installed `@base-ui/react`, and also `cn`, `shadcn`, `tw-animate-css` and the Geist font, and ignored the aliases. The extras were removed and the aliases restored. Primitives were taken from `shadcn add --dry-run --view` and adapted by hand, because `add` would reinstall `cn`. Tailwind v4's native `data-checked:` variant replaces `shadcn/tailwind.css`.
- **Figma values not exported as variables:** tertiary button colours, input borders and topbar background may be raw fills.
  - Mitigation: read them with `get_design_context` on the specific symbol nodes listed in Context.
  - Where no value exists, use the nearest scale step and note it in the task.
- **Trade-off — wrappers duplicate a little API surface** (contract wrapper + primitive). This is accepted to keep flows unchanged.
- **Trade-off — the frame is fixed at the iPhone 15/16 size** (393×852). Flows tested on other device sizes aren't represented. That's acceptable for now.

## Migration Plan

Additive, single PR in `apps/app-ux-flows`. There's no data or storage migration. Rollback means reverting the commit and `pnpm install`.

Commands the user runs or approves:
- `pnpm --filter app-ux-flows add …`
- `pnpm dlx shadcn@latest init` / `add`, run inside `apps/app-ux-flows`
