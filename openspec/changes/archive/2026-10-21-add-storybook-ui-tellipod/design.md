## Context

- app-tellipod is an Expo (SDK 58) app on RN 0.88 with `expo-router` entry (`main: expo-router/entry`), a Metro config already set up for the pnpm monorepo (`watchFolders` and `nodeModulesPaths` at the workspace root), and `@mee/ui` consumed from source (`main: src/index.ts`).
- `@mee/ui` has no app of its own and currently contains only `Button`. It has no dev server, so it cannot host Storybook by itself.
- App runtime context is set up in `src/app/_layout.tsx`: i18n import, Public Sans fonts, `SafeAreaProvider`.
- Specs are scoped per app and per package (see `openspec/config.yaml`), hence two capabilities.

## Goals / Non-Goals

**Goals:**
- One Storybook, run from app-tellipod, that shows both `@mee/ui` and app-tellipod components on a device or simulator.
- Stories colocated with the component they describe.
- No effect on the normal app unless the flag is set.

**Non-Goals:**
- Web Storybook, visual regression or snapshot services, Chromatic, hosted deployment.
- Stories for screens that depend on router or global state (onboarding screen, pod screens).
- Storybook in `app-concepts` or `app-production`.
- Introducing a shadcn-style component set or restyling existing components.

## Decisions

1. **On-device Storybook (`@storybook/react-native`) over web Storybook with `react-native-web`.** The app uses Reanimated, SVG, gesture handler and `expo-linear-gradient`, which need extra web shims and render differently from native. On-device matches real rendering. Trade-off: slower iteration than a browser, and no browser addon ecosystem.

2. **Host in app-tellipod; `@mee/ui` stories are included through the story glob.** `@mee/ui` has no runtime of its own, and a second host would duplicate the Metro, Babel and Expo setup. The `main.ts` globs cover `packages/ui/src/**/*.stories.tsx` and `apps/app-tellipod/src/**/*.stories.tsx`. A story title prefix (`UI/…` and `Tellipod/…`) separates the groups. Alternative considered: a dedicated `apps/storybook` Expo app; rejected as more native projects to maintain for one consumer.

3. **Switch at the entry point with an env flag (`EXPO_PUBLIC_STORYBOOK=true`).** `expo-router/entry` stays the entry. The Metro `withStorybook` wrapper is given `enabled` from the env flag, and the root layout returns the Storybook root before rendering the header, guards and `Stack` when the flag is on. Alternative: a dedicated `/storybook` route. Rejected because the root layout loads the header chrome, onboarding guards and `Stack.Protected` redirects, which would intercept the route.

4. **Shared decorator in `.rnstorybook/preview.tsx`** wraps stories in `SafeAreaProvider` and loads i18n and the Public Sans fonts (waiting for them before rendering), mirroring `_layout.tsx`. Reason: faithful rendering without duplicating app logic per story. Components that read Jotai atoms get a fresh `Provider` per story so state does not leak between stories.

5. **Controls and actions via `@storybook/addon-ondevice-controls` and `-actions`.** Press handlers use `fn()`/`action` args, and prop controls come from `argTypes` on each story.

6. **Stories are CSF3 `*.stories.tsx`, type-checked and linted like other source.** `packages/ui` stories import types from `@storybook/react-native` as a devDependency only; `src/index.ts` does not export them. Jest ignores `*.stories.tsx`.

7. **Generated `storybook.requires.ts` is gitignored** and regenerated by the Metro wrapper and a `storybook-generate` script, so it never drifts from the story globs.

## Risks / Trade-offs

- [Storybook code leaks into the production bundle] → Gate the import behind the env flag, which is inlined by `babel-preset-expo`, so the Storybook chunk is dead code when off; verify in a release bundle.
- [Metro does not resolve or watch `packages/ui` stories] → The existing `watchFolders` already covers the workspace root; verify by editing a `@mee/ui` story with the app running.
- [Peer-version mismatch with RN 0.88 / React 19.3] → Pin the latest compatible `@storybook/react-native` 9.x and confirm it bundles; if it does not, record the blocker rather than downgrading RN.
- [Reanimated or the header widgets break outside the app tree] → Provide the needed providers in the decorator; stories for components that cannot be isolated are skipped and documented.
- [Native module additions require a rebuild] → Choose dependencies that are JS-only or already in the app (`react-native-safe-area-context`, `react-native-gesture-handler`, `react-native-reanimated`). Any new native dependency (such as `@react-native-async-storage/async-storage` or `@gorhom/bottom-sheet`) will need `expo prebuild` or a dev build, which is flagged to the user before running.
